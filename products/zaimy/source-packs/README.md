# Source packs для МФО

Файл `organizations/<slug>.md` вставляется в окно админки «Заполнить карточку через AI». У каждой организации один файл с двумя частями:

1. Точные данные для полей карточки.
2. Сырой контент официального сайта для описаний и FAQ.

## Структура

```text
source-packs/
  README.md
  organizations/
    <organization-slug>.md
```

## Формат файла

Состав верхнего блока определяется в `products/zaimy/landings/company/README.md`. Здесь не дублируем поля карточки: новые разделы добавляются в source pack только после согласования в брифе лендинга.

```text
# <Бренд>

Официальный сайт: https://...

## Данные карточки компании

<разделы и поля из products/zaimy/landings/company/README.md>

## Контент официального сайта

<сырой текст официальных страниц подряд, без добавленных подписей между страницами>
```

В верхней части указываем только поля, согласованные в брифе карточки компании. Статус карточки, ответственного и внутренние заметки не собираем: это редакционные настройки команды.

## Уровни доверия источников

| Уровень | Источники | Как используем |
| --- | --- | --- |
| Tier 1 | Банк России, ФНС/ЕГРЮЛ, официальный сайт и документы компании | Единственный источник значений для импорта. |
| Tier 2 | Банки.ру, Сравни, Финуслуги, Bankiros и другие каталоги | Помогают найти и перепроверить данные, но не заполняют поля. |

Если источники Tier 1 расходятся: Банк России главный для статуса и записи в реестре, ФНС — для реквизитов, официальный документ — для условий, официальный сайт — для бренда, контактов и контента. Для одного ключа передаём AI только одно проверенное значение; если его нет, пишем `Не указано`.

## Источники Tier 1 для данных карточки

Используем только официальные источники:

1. Карточка участника финансового рынка Банка России: статус, юридическое наименование, номер записи в реестре, дата начала деятельности, тип МФО.
2. Официальный сайт организации: бренд, официальный сайт, публичные контакты, адреса и режим работы.
3. Официальные документы организации: КПП, реквизиты, правила, суммы, сроки, ставки и ПСК.
4. ФНС/ЕГРЮЛ: только для обязательного реквизита, которого нет в официальных документах компании, или для разрешения конфликта между ними.
5. Реестр СРО: только когда в админке нужна отдельная запись о членстве в СРО.

Tier 2 не используем как источник импорта.

В файл добавляем только нужные ссылки: официальный сайт, карточку ЦБ и, при необходимости, прямую ссылку на официальный документ или ЕГРЮЛ. Не повторяем URL у каждого значения.

## Приоритет и конфликты

Перед передачей файла AI выбираем одно точное значение для каждого поля:

- Банк России: статус, номер записи в реестре, дата начала деятельности, юридическое наименование и тип МФО.
- Официальный документ: КПП, банковские реквизиты, условия, суммы, сроки, ставки и ПСК.
- Официальный сайт: бренд, контакты, адреса, режим работы, описание и FAQ.
- ФНС/ЕГРЮЛ: обязательный реквизит при отсутствии или конфликте официальных данных компании.

Не передаём AI две версии одного значения и не пишем объяснение конфликта. Если в документе указано несколько КПП, сначала проверяем актуальный основной КПП по ФНС/ЕГРЮЛ и только затем указываем одно значение в блоке реквизитов.

## Контент официального сайта

Ниже блока данных переносим буквальный текст официальных страниц. Он нужен AI для краткого и полного описания организации, а также FAQ.

Для МФО обычно нужны:

- главная страница;
- «О компании»;
- FAQ или помощь;
- получение и погашение займа;
- другие официальные страницы, где раскрыты особенности обслуживания.

Не делаем выжимку, не переписываем текст своими словами и не добавляем ответы FAQ от себя. Не вставляем индекс документов целиком, страницы с чужими компаниями или нерелевантные разделы. Между скопированными страницами не добавляем названия, URL, даты или комментарии.

## Проверка импорта

1. Сначала собираем блок данных и добавляем к нему уже проверенный текст главной страницы.
2. Проверяем импорт в админке.
3. Добавляем остальные официальные страницы по одной и повторяем проверку.
4. Если импорт перестал проходить, убираем последнюю добавленную страницу. Блок данных и уже проверенный контент не переписываем наугад.
