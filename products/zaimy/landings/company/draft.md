# Draft: `/companies/{slug}/`

Статус: рабочий набросок карточки МФО.

## Назначение

Карточка помогает проверить организацию, понять общие условия её займов и разобраться в получении и обслуживании. Это не продуктовый хаб, не витрина именованных офферов и не обзор отзывов.

Этот файл — рабочий бриф страницы и контракт данных. Правила источников лежат в `products/zaimy/landings/company/source-packs/README.md`.

Пока таблицы не согласованы, сбор не начинаем. После согласования этот файл станет `final.md`, а по его таблицам создадим один утверждённый шаблон в `source-packs/template.md`.

## Контракт результата сбора

Успешный результат — один Markdown-файл по утверждённому шаблону. В нём находятся только проверенные значения полей, список использованных официальных источников и буквальный контент официального сайта.

В файл не добавляем готовый текст страницы, FAQ, SEO, объяснения конфликтов, отчёт о поиске или рекомендации для админки.

### Допустимые значения

Одинаковые формулировки обязательны во всех файлах. Не используем варианты `нет данных`, `не найдено`, `неизвестно`, прочерк или пустое значение.

| Тип данных | Допустимые значения |
| --- | --- |
| Статус в реестре | `Действует` / `Исключена` |
| Тип организации | `МФК` / `МКК` |
| Логический факт | `Да` / `Нет` / `Не указано` |
| Доступность условия | `Да` / `Нет` / `Зависит от условий займа` / `Не указано` |
| Формат оформления | `Онлайн` / `Офлайн` / `Онлайн и офлайн` / `Не указано` |
| Требование банковской карты | `Требуется` / `Не требуется` / `Зависит от способа получения` / `Не указано` |
| График погашения | `Единым платежом` / `По графику` / `Оба варианта` / `Не указано` |

### Если значение не найдено

| Ситуация | Что записываем в итоговый файл |
| --- | --- |
| Официальный источник публикует точное значение | Переносим значение без перефразирования |
| Официальный источник прямо подтверждает отсутствие условия | `Нет` |
| Официальные источники не упоминают необязательное поле | `Не указано` |
| Родительское условие делает зависимое поле бессмысленным | `Не применимо` |
| У действующих займов одной организации подтверждены разные значения | `Зависит от условий займа` или общий подтверждённый диапазон |
| Tier 1 противоречат друг другу, и приоритет источников не разрешает конфликт | Файл не формируем; просим ручную проверку |
| Не найдено обязательное поле | Файл не формируем; перечисляем недостающие поля в ответе пользователю, но не внутри source pack |

`Нет` нельзя выводить из отсутствия информации. `Не применимо` используем только для зависимого поля: например, если первый займ без процентов — `Нет`, то срок и условие ставки 0% — `Не применимо`.

### Обязательный минимум

Без этих значений файл не считаем готовым:

- бренд;
- официальный сайт;
- тип организации;
- полное юридическое наименование;
- ИНН, ОГРН и КПП;
- статус, название, основной номер и дата внесения в реестр Банка России;
- юридический адрес;
- карточка Банка России;
- ФНС / ЕГРЮЛ или реквизиты официальной проверки;
- дата проверки.

Если отдельный почтовый адрес не опубликован, используем юридический адрес. Это согласованное резервное правило, а не значение `Не указано`.

Если Банк России указывает статус `Исключена`, не продолжаем обычный сбор условий и сначала сообщаем пользователю. Исторические условия не переносим как действующие.

## Правила данных

1. Названия полей и разделов в шаблоне не меняем: это контракт выходного файла.
2. Для каждого поля передаём одно проверенное значение. Конфликты разрешаем до формирования файла.
3. Если необязательного официального значения нет, пишем `Не указано`. Не добавляем пояснения о том, где и почему поле не найдено.
4. Для полей с конечным набором значений используем только статусы из раздела «Допустимые значения».
5. Денежные значения указываем в рублях, сроки и ставки — с официальной единицей измерения. Не пересчитываем месяцы в дни, годовую ставку в дневную или ПСК в ставку самостоятельно.
6. Условия собираем только по действующим потребительским займам самой организации. Для диапазонов берём внешние границы всех подтверждённых действующих условий. Рекламу других юридических лиц и каталожные значения не переносим.
7. Краткое и полное описание, FAQ и SEO генерирует AI из официального контента. В блок точных данных их не пишем.
8. Похожие МФО формирует сайт автоматически. В source pack этот блок не передаём.
9. Номер лицензии не собираем и не подменяем номером записи в реестре МФО.

### Нормализация итогового файла

1. Используем только заголовки, строки `Ключ: значение` и маркированные списки из шаблона. Таблицы, HTML, JSON, кодовые блоки и сноски в source pack не добавляем.
2. Все плейсхолдеры заменяем. Пустых строк после двоеточия и пустых пунктов списка не оставляем.
3. Суммы записываем целым числом и единицей: `1000 ₽`. Сроки — числом и официальной единицей: `7 календарных дней`, `3 месяца`. Ставки — числом и единицей: `0.8% в день`, `292% годовых`.
4. Даты записываем только как `дд.мм.гггг`.
5. ИНН, ОГРН, КПП и номера реестров записываем цифрами без пояснений внутри значения.
6. Телефон приводим к единому читаемому формату с кодом страны, email — к нижнему регистру, URL — к полному каноническому адресу без рекламных параметров.
7. Используем обычные пробелы. Неразрывные пробелы, скрытые символы и технические плейсхолдеры в итоговом файле запрещены.
8. Повторяющиеся элементы списков удаляем, порядок сохраняем по официальному источнику.

### Несколько действующих условий

1. Сначала проверяем дату и период действия документов. Архивные и утратившие силу условия не используем.
2. Для суммы, срока, ставки и ПСК берём минимальную и максимальную внешние границы по всем подтверждённым действующим потребительским займам организации.
3. Для способов получения, погашения, идентификации и документов объединяем подтверждённые значения без дублей.
4. Если функция доступна не для всех действующих займов, записываем `Зависит от условий займа`.
5. Если текстовые условия различаются, не склеиваем их в одно утверждение. В поле доступности ставим `Зависит от условий займа`, а в зависимом текстовом поле кратко перечисляем подтверждённые варианты без названий продуктов.
6. Именованные продукты и офферы в source pack организации не добавляем.

### Пограничные ситуации

| Ситуация | Действие сборщика |
| --- | --- |
| Официальный сайт временно недоступен или закрыт технической защитой | Не заменять его каталогом, кэшем или поисковым сниппетом; остановить сбор и сообщить пользователю |
| Домен перенаправляет на другой бренд | Сначала подтвердить новое юридическое лицо по ФНС и Банку России; при несовпадении остановить сбор |
| На одном сайте работают несколько юридических лиц | Брать только сведения юрлица, которое выдаёт рассматриваемые займы; если разделить сведения нельзя, остановить сбор |
| Значение найдено только у Банки.ру, Сравни или другого Tier 2 | Для необязательного поля записать `Не указано`; для обязательного — остановить сбор |
| Найден архивный документ или документ с истёкшим периодом действия | Не использовать значение |
| Найден документ, который ещё не вступил в силу | Не использовать до даты вступления в силу |
| Два действующих официальных документа противоречат друг другу | Использовать более поздний документ только при явной замене предыдущего; иначе остановить сбор |
| Страница сайта противоречит действующему официальному документу | Для условий использовать официальный документ; страницу оставить только как сырой контент без спорного значения в блоке данных |
| На сайте осталась завершившаяся акция | Не считать её действующим условием |
| Первый займ заявлен как беспроцентный только при выполнении условий | Записать `Да` или `Зависит от условий займа` и обязательно перенести точное условие ставки 0% |
| Есть только рекламная формулировка `за минуту`, `мгновенно`, `до зарплаты` без точного значения | Записать `Не указано` в числовое поле; рекламный текст не нормализовать в число |
| Источник не указывает верхнюю границу возраста, суммы или срока | Записать `Не указано`; не выводить `Не ограничено` самостоятельно |
| Условия указаны в месяцах, неделях или днях | Не приводить их к другой единице самостоятельно; сохранить официальное значение и единицу |
| Дневная ставка не опубликована, но есть годовая ставка или ПСК | Не рассчитывать дневную ставку; записать `Не указано` |
| Указан только контакт пресс-службы, партнёров или для рекламы | Не использовать его как контакт поддержки |
| Опубликовано несколько телефонов или email | Выбрать основной клиентский контакт; не объединять поддержку, претензии, партнёрство и пресс-службу в одно поле |
| Опубликовано несколько адресов | Юридический адрес взять из ФНС, почтовый — из официального сайта или документа; адреса офисов и пунктов выдачи не подставлять |
| Юридический и почтовый адрес совпадают или отдельный почтовый адрес не опубликован | Повторить юридический адрес в поле почтового адреса |

## Корпус официального контента

После блока точных данных в том же Markdown-файле добавляем сырой контент максимум трёх страниц официального сайта. Он нужен для будущего краткого и полного описания организации, а также FAQ.

```md
## Контент официального сайта

### Главная
<буквальный полезный текст страницы>

### О компании
<буквальный полезный текст страницы>

### Помощь и FAQ
<буквальный полезный текст страницы>
```

Первые две страницы всегда: `Главная` и `О компании`. Третья — `Помощь и FAQ`. Если такой страницы нет или в ней мало содержания, вместо неё берём одну наиболее содержательную страницу: `Получение займа`, `Погашение займа` или `Условия займа` и используем её фактическое название в заголовке.

Переносим весь смысловой видимый текст выбранной страницы без редакторской выжимки. Не добавляем URL под каждым заголовком, даты сбора, комментарии, меню, cookie-баннеры, повторяющийся футер, отзывы, офферные карточки, рекламные блоки и сведения других юридических лиц.

Документы пока используем для точных полей в верхней таблице. Полный текст правил и PDF в первые три страницы не добавляем: он перегружает контекст и не нужен для описания компании. Если позже не хватит официального ответа для важной темы, отдельно решим, какие дословные фрагменты документа добавить.

## Промпт будущему сборщику

**Вход:** бренд МФО и/или URL её официального сайта.

**Выход:** ровно один файл `organizations/<slug>.md` по утверждённому шаблону. Не создавать рядом отчёт, выжимку, список конфликтов или дополнительные файлы.

Если сработало условие остановки, файл не создавать. В ответе пользователю кратко указать причину и конкретные поля или источники, которые требуют ручной проверки.

1. Подтвердить текущий бренд и канонический официальный домен.
2. Установить юридическое лицо по официальному сайту и связать его с Банком России и ФНС по ИНН или ОГРН. Если связь не подтверждается, остановить сбор.
3. Проверить статус в реестре. При статусе `Исключена` остановить обычный сбор и сообщить пользователю.
4. Сначала заполнить обязательный минимум по Банку России, ФНС и официальному сайту.
5. Найти только действующие официальные документы и страницы с условиями, требованиями, получением, погашением, продлением, просрочкой и помощью.
6. Собрать значения по каждому полю, применяя правила агрегации, приоритетов и пограничных ситуаций.
7. После утверждения таблиц заполнить единый шаблон, созданный по этому брифу. Названия разделов и полей не менять, пустых полей не оставлять.
8. После точных данных добавить сырой контент трёх страниц по разделу «Корпус официального контента». Не делать выжимку и не добавлять URL, даты или комментарии между страницами.
9. Проверить, что в файле нет двух значений одного поля, чужих юридических лиц, архивных условий, каталожных данных, отзывов и редакционных догадок.
10. Сохранить ровно один готовый Markdown-файл. Загрузку в админку в рамках этого промпта не выполнять.

## Критерий готовности source pack

- Заполнены бренд, официальный сайт, тип организации, полное юридическое наименование, ИНН, ОГРН и КПП.
- Заполнены статус, основной номер и дата внесения в реестр Банка России.
- Заполнены юридический и почтовый адреса; если отдельного почтового адреса нет, повторён юридический.
- Указаны карточка Банка России и дата проверки.
- Условия имеют единицы измерения и относятся к самой организации.
- В итоговом файле осталась одна версия каждого значения.
- Все конечные статусы совпадают с разделом «Допустимые значения».
- Зависимые поля согласованы: при `Нет` используется `Не применимо`, при отсутствии сведений — `Не указано`.
- Использованы только действующие документы; даты и единицы измерения сохранены без самостоятельных расчётов.
- В файле не осталось маркеров `[ЗАПОЛНИТЬ]`.
- Источники Tier 1 перечислены один раз.
- Перенесён весь доступный релевантный официальный контент; отсутствующие темы не дописаны от себя.
- Файл содержит только поля шаблона и официальный контент, предусмотренный этим брифом.
