# Source packs для МФО

В этой папке хранятся проверенные данные для карточек организаций. Для каждой МФО создаётся один Markdown-файл с таблицами, редакционными блоками и использованными источниками. Сырой текст сайтов, документов и отзывов в source pack не сохраняется.

## Структура

```text
source-packs/
  README.md
  template.md
  organizations/
    <organization-slug>.md
    <organization-slug>-final.md
```

## Роли файлов

- `../final.md` — единственная утверждённая спецификация, контракт данных и промпты сборщика, редактора и аналитика отзывов.
- `template.md` — канонические названия, порядок разделов и полей готового source pack.
- `organizations/<organization-slug>.md` — зарезервированный или находящийся в работе source pack конкретной организации.
- `organizations/<organization-slug>-final.md` — полностью собранный, проверенный и одобренный source pack. `organizations/lime-zaim-final.md` служит эталоном оформления, но не является источником фактов для других МФО и не заменяет правила спецификации.

Пустой файл без суффикса `-final` означает, что для организации зарезервирован целевой путь, но сбор ещё не начат. Суффикс `-final` добавляем только после завершения всех предусмотренных этапов и финальной проверки по `../final.md`.

Приоритет при расхождениях: `../final.md` определяет смысл и правила, `template.md` — структуру результата, пример Лайма — только оформление подтверждённых значений.

## Рабочий порядок

1. Сборщик проверяет обязательные источники по `../final.md`.
2. После успешной проверки поэтапно заполняет `organizations/<organization-slug>.md` на основе `template.md`, используя `lime-zaim-final.md` только как пример оформления.
3. Готовую фактическую базу проверяет по критериям спецификации.
4. Редактор готовит описание и FAQ, а после явного одобрения пользователя добавляет их в тот же файл.
5. Аналитик независимо готовит обзор отзывов по правилам `../final.md` и после одобрения добавляет сформированный блок в тот же файл.
6. После каждого этапа сохраняет и отправляет изменения в Git.
7. После завершения всех предусмотренных этапов и финальной проверки переименовывает файл в `<organization-slug>-final.md` и отправляет переименование в Git.
8. Завершённый файл отдельно передаётся в AI-окно админки.
