# Source packs для МФО

После согласования формата для каждой организации собираем один файл `organizations/<slug>.md` с двумя частями:

1. Точные данные для полей карточки.
2. Сырой контент официального сайта для описаний и FAQ.

Сейчас таблицы и правила ещё обсуждаются, поэтому файлы организаций оставлены пустыми. Рабочий бриф и промпт сборщика находятся в `../draft.md`.

## Структура

```text
source-packs/
  README.md
  organizations/
    <organization-slug>.md
```

## Формат файла

Каноническая схема полей пока обсуждается в `products/zaimy/landings/company/draft.md`. Отдельного заполняемого шаблона пока нет.

После согласования создаём один шаблон в `source-packs/template.md`. Только после этого копируем его в `organizations/<slug>.md` и заполняем по правилам брифа. Названия разделов и полей не меняем.

Используем только точное значение или контролируемые ответы `Не указано`, `Не применимо` и `Зависит от условий займа` по правилам `../draft.md`.

В верхней части указываем только поля, согласованные в рабочей схеме карточки компании. Статус карточки, ответственного и внутренние заметки не собираем: это редакционные настройки команды.

## Уровни доверия источников

| Уровень | Источники | Как используем |
| --- | --- | --- |
| Tier 1 | Банк России, ФНС/ЕГРЮЛ, официальный сайт и документы компании | Единственный источник значений итогового файла. |
| Tier 2 | Банки.ру, Сравни, Финуслуги, Bankiros и другие каталоги | Могут помочь найти официальный источник, но сами не подтверждают значение и не заполняют поле. |

Если источники Tier 1 расходятся: Банк России главный для статуса и записи в реестре, ФНС — для реквизитов, официальный документ — для условий, официальный сайт — для бренда, контактов и контента. Для одного ключа оставляем только одно проверенное значение. Если приоритет не разрешает конфликт, файл не формируем до ручной проверки.

## Источники Tier 1 для данных карточки

Используем только официальные источники:

1. Карточка участника финансового рынка Банка России: статус, номер записи в реестре, дата внесения в реестр и тип МФО.
2. Официальный сайт организации: бренд, официальный сайт, публичные контакты, адреса и контент.
3. Официальные документы организации: правила, суммы, сроки, ставки, ПСК и особенности обслуживания.
4. ФНС/ЕГРЮЛ: актуальное юридическое наименование, ИНН, ОГРН, КПП, юридический адрес и разрешение конфликтов по реквизитам.
5. Официальный реестр СРО: членство, название СРО, номер записи и дата вступления.

Tier 2 не используем как источник значений итогового файла.

В файл добавляем только нужные ссылки: официальный сайт, карточку Банка России, проверку ФНС/ЕГРЮЛ и использованные официальные документы. Не повторяем URL у каждого значения.

## Приоритет и конфликты

Перед формированием файла выбираем одно точное значение для каждого поля:

- Банк России: статус, номер записи в реестре, дата внесения в реестр и тип МФО.
- Официальный документ: условия, суммы, сроки, ставки, ПСК и особенности обслуживания.
- Официальный сайт: бренд, контакты, адреса и сырой контент для описаний и FAQ.
- ФНС/ЕГРЮЛ: актуальное юридическое наименование, ИНН, ОГРН, КПП и юридический адрес.
- Официальный реестр СРО: членство, название СРО, номер записи и дата вступления.

Не сохраняем две версии одного значения и не пишем объяснение конфликта внутри source pack. Если в документе указано несколько КПП, сначала проверяем актуальный основной КПП по ФНС/ЕГРЮЛ и только затем указываем одно значение в блоке реквизитов.

## Контент официального сайта

Ниже блока данных переносим буквальный текст трёх страниц официального сайта. Он станет сырьём для будущего краткого и полного описания организации, а также FAQ.

Для первого прохода берём:

- главная страница;
- «О компании»;
- FAQ или помощь.

Если FAQ или помощь отсутствуют либо почти пустые, третьей берём одну наиболее содержательную страницу: «Получение займа», «Погашение займа» или «Условия займа».

Используем заголовки `### Главная`, `### О компании` и фактическое название третьей выбранной страницы. Не делаем выжимку, не переписываем текст своими словами и не добавляем ответы FAQ от себя. Не вставляем индекс документов целиком, страницы с чужими компаниями, нерелевантные разделы, URL, даты или комментарии между страницами.

## Проверка готового файла

1. Пустых полей и пустых пунктов списков нет.
2. Все конечные статусы записаны строго по `../draft.md`.
3. Обязательный минимум заполнен и проверен.
4. В каждом поле осталось одно значение без комментария о процессе поиска.
5. В файл добавлен буквальный официальный контент без выжимки и дописанных ответов.
6. Результат — один Markdown-файл; загрузка в админку выполняется отдельно.
