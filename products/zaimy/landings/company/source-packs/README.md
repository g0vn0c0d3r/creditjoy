# Source packs для МФО

В этой папке хранятся проверенные данные для карточек организаций. Для каждой МФО создаётся один Markdown-файл с таблицами, редакционными блоками и использованными источниками. Сырой текст сайтов, документов и отзывов в source pack не сохраняется.

## Структура

```text
source-packs/
  README.md
  template.md
  examples/
    lime-zaim.md
  organizations/
    <organization-slug>.md
```

## Роли файлов

- `../final.md` — единственная утверждённая спецификация, контракт данных и промпты сборщика, редактора и аналитика отзывов.
- `template.md` — канонические названия, порядок разделов и полей готового source pack.
- `examples/lime-zaim.md` — эталон полностью собранного и одобренного результата. Он показывает формат и уровень детализации, но не является источником фактов для других МФО и не заменяет правила спецификации.
- `organizations/<organization-slug>.md` — фактический source pack конкретной организации. Имя файла всегда совпадает со слагом бренда.

Пустой файл в `organizations/` означает, что для организации зарезервирован целевой путь, но сбор ещё не начат. Готовым считается только файл, прошедший проверки из `../final.md`.

Приоритет при расхождениях: `../final.md` определяет смысл и правила, `template.md` — структуру результата, пример Лайма — только оформление подтверждённых значений.

## Рабочий порядок

1. Сборщик проверяет обязательные источники по `../final.md`.
2. После успешной проверки поэтапно заполняет один файл в `organizations/` на основе `template.md`, используя Лайм только как пример оформления.
3. Готовую фактическую базу проверяет по критериям спецификации.
4. Редактор готовит описание и FAQ, а после явного одобрения пользователя добавляет их в тот же файл.
5. Аналитик независимо готовит обзор отзывов по правилам `../final.md` и после одобрения добавляет сформированный блок в тот же файл.
6. После каждого этапа сохраняет и отправляет изменения в Git.
7. Завершённый файл отдельно передаётся в AI-окно админки.
