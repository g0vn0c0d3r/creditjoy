# creditjoy

Рабочий проект для анализа структуры финансовых маркетплейсов и подготовки семантики под будущий сайт.

Смотрим на игроков:

- banki.ru
- sravni.ru
- bankiros.ru
- finuslugi.ru
- ru.myfin.by

Первый фокус проекта - займы и микрозаймы. Сейчас мы не утверждаем будущие страницы и не дробим семантику заранее. Сначала разбираем объединенный файл запросов и руками выбираем, что точно подходит под коммерческие страницы.

## Что уже сделано

- Создан локальный git-репозиторий.
- Сохранены исходные Wordcraft-файлы в git с короткими понятными именами.
- Собрана карта структуры конкурентов: главная, продуктовые страницы, модификаторы, гео, бренды, рейтинги и support-страницы.
- Подготовлена стартовая стратегия сайта и вертикали `займы`.
- Объединены 3 Wordcraft-файла в один рабочий файл `data/keywords.csv`.
- Колонка `cluster` из Wordcraft полностью игнорируется.
- Запросы дедублицированы по нормализованному тексту.
- Для повторяющихся запросов сохранены максимальные `clicks` и `demand`, без суммирования между файлами.

## Главные файлы

- `docs/competitor-structure.md` - как устроена глубина у конкурентов.
- `docs/strategy.md` - наша стратегия: структура сайта, структура продукта `займы`, гео, модификаторы, антидубли.
- `docs/keyword-processing.md` - как собирается единый файл запросов.
- `data/raw/wordcraft/` - исходные Excel-файлы Wordcraft.
- `data/keywords.csv` - главный рабочий файл со всеми словами.
- `scripts/build-keywords.mjs` - скрипт, который пересобирает `data/keywords.csv` из исходных Excel-файлов.

## Рабочий файл слов

`data/keywords.csv` - единственный файл, с которым дальше работаем руками.

Поля:

- `query` - запрос.
- `clicks` - клики из Wordcraft.
- `demand` - спрос из Wordcraft.
- `sources` - из каких исходных файлов пришел запрос.
- `decision` - пустое поле для нашего будущего решения.
- `notes` - пустое поле для заметок.

Текущий объем: 5 507 уникальных запросов.

## Дальше

Следующий этап - несколько ручных проходов по `data/keywords.csv`:

1. Сначала выбираем то, что точно подходит под коммерческие страницы.
2. Потом отдельно смотрим сомнительные запросы.
3. После этого уже собираем будущие slug'и и кластеры под страницы.

Главный принцип на текущем этапе: один общий файл слов, без преждевременной нарезки на бакеты и страницы.
