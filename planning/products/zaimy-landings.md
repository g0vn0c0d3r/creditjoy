# Лендинги продукта: займы

Статус: рабочее ТЗ по типам лендингов и содержанию страниц.

Дата: 2026-08-02.

## Зачем документ

Мы уже поняли схему продукта `займы`: есть продуктовый хаб, интентные страницы, гео и комбинации `интент + город`.

Теперь нужно понять, какие лендинги будут внутри этой схемы и что на них должно быть.

Этот файл можно отдать редактору, дизайнеру, SEO-специалисту или другой ИИ-системе как вводный документ для проектирования лендингов.

Связанные файлы:

- `planning/products/zaimy-structure.md` - схема продукта, URL и масштабирование.
- `ROADMAP.md` - верхний план, стратегия и конкуренты.
- `data/competitor-loan-slugs.csv` - полный рыночный список найденных слагов.
- `data/keywords.csv` - семантика, которую потом привязываем к выбранным лендингам.

## От чего отталкиваемся

По конкурентам видно, что базовая логика рынка уже сложилась:

```text
продукт -> интент -> гео -> оффер/компания -> доверие/FAQ/отзывы
```

Мы не пытаемся придумать новую структуру с нуля. Берем рабочую рыночную модель и делаем страницы полезнее.

Что берем у конкурентов:

- `Sravni.ru` - быстрый подбор, понятная витрина, короткие переходы в интенты и гео.
- `Bankiros.ru` / `Myfin` - широкая матрица интентов, гео и справочников.
- `Brobank.ru` - насыщенные коммерческие страницы с объяснениями и готовыми решениями.
- `Banki.ru` - доверие, отзывы, рейтинги, карточки компаний.
- `Finuslugi.ru` - аккуратная теговая модель и официальный тон.
- `Zaym.me` - масштабирование через матрицу `интент x город`.

Вывод: структура должна быть простой, а преимущество CreditJoy должно появляться в данных, полезности, прозрачности условий и связке страниц.

## SEO-принцип

Для финансовой темы страница должна не просто ловить запрос, а помогать человеку принять решение.

Базовые правила:

- один URL - один понятный сценарий выбора;
- не плодим страницы ради синонимов;
- интент становится лендингом только если отличается потребность, выдача, набор офферов или полезный контент;
- коммерческий блок должен быть выше длинного текста;
- условия должны быть прозрачными: ставка, ПСК, срок, сумма, комиссии, подписки, страховки;
- на странице должно быть понятно, кто и как собрал данные;
- гео-страница должна давать локальную пользу, а не только менять название города;
- перелинковка должна вести пользователя дальше: продукт -> интенты -> города -> компании -> блог/FAQ.

Официальные ориентиры:

- Google: полезный, надежный, people-first контент и E-E-A-T для финансовых тем - https://developers.google.com/search/docs/fundamentals/creating-helpful-content
- Google: понятная структура сайта, описательные URL, полезный контент - https://developers.google.com/search/docs/fundamentals/seo-starter-guide
- Яндекс: качество сайта, полезность для пользователя, отсутствие дублей, понятные URL и мета-данные - https://yandex.ru/support/webmaster/ru/site-quality-index

## Что считать лендингом

Лендинг - это не любой фильтр. Это страница, у которой есть отдельный URL, отдельный смысл и отдельная польза.

Фильтр или тег можно превратить в лендинг, если выполняется несколько условий:

- интент найден у конкурентов или в семантике;
- под него можно показать релевантные офферы;
- страница будет отличаться от родителя не только H1/title;
- есть что объяснить пользователю: условия, риски, критерии выбора;
- есть куда перелинковать страницу внутри продукта.

Если отличие только в синониме, оставляем как алиас к канонической странице.

Пример:

- `займы на карту`, `займы онлайн на карту`, `микрозаймы на карту` могут вести к одной канонической странице `/zaimy/na-kartu/`;
- `займы под залог ПТС` и `займы под залог недвижимости` лучше держать разными страницами, потому что отличаются обеспечение, риски, документы и условия;
- `без отказа` и `без проверок` не берем как чистые стартовые лендинги без отдельной юридической и SEO-проверки.

## Типы лендингов

```text
/
|-- /zaimy/ - продуктовый хаб
|   |-- /zaimy/{intent}/ - интентный лендинг
|   |   `-- /zaimy/{intent}/{city}/ - интент в городе
|   |
|   `-- /zaimy/{city}/ - продукт в городе
|
|-- /companies/{slug}/ - карточка компании
|-- /blog/{slug}/ - блог или справка
`-- /calculators/{slug}/ - калькулятор или сервис
```

## Общий стандарт коммерческой страницы

Каждая коммерческая страница должна собираться из одних и тех же смысловых блоков, но с разным акцентом.

Базовый порядок:

1. Хлебные крошки.
2. H1 и короткое объяснение страницы.
3. Быстрые фильтры или форма подбора.
4. Список офферов.
5. Карточки МФО с условиями.
6. Таблица сравнения.
7. Блок доверия: как проверяем данные, дата обновления, лицензии/реестр, важные ограничения.
8. Объясняющий текст по интенту.
9. FAQ.
10. Перелинковка на соседние интенты, города, компании, блог и калькуляторы.

Главное правило: коммерческая польза сверху, объясняющий текст ниже.

## Продуктовый хаб `/zaimy/`

Роль: главная витрина продукта.

Что должен закрывать:

- человек хочет выбрать займ, но еще не уточнил сценарий;
- нужно быстро показать предложения, фильтры и основные направления;
- это центр перелинковки на интенты, гео, компании и справочные материалы.

Что на странице:

- H1: `Займы`;
- короткое описание без воды;
- фильтры: сумма, срок, способ получения, залог, кредитная история, город;
- список офферов;
- блок популярных направлений: `на карту`, `без процентов`, `с плохой КИ`, `под залог ПТС`, `под залог недвижимости`;
- блок городов;
- таблица сравнения условий;
- карточки популярных МФО;
- объяснение, как выбрать займ;
- FAQ;
- ссылки на блог и калькуляторы.

## Интентный лендинг `/zaimy/{intent}/`

Роль: страница под один понятный сценарий выбора.

Примеры:

- `/zaimy/na-kartu/`;
- `/zaimy/bez-procentov/`;
- `/zaimy/s-plohoy-kreditnoy-istoriey/`;
- `/zaimy/pod-zalog-pts/`;
- `/zaimy/pod-zalog-nedvizhimosti/`.

Что должно отличаться от `/zaimy/`:

- H1 и первый экран говорят о конкретном сценарии;
- список офферов фильтруется по тегу интента;
- фильтры и подсказки подстраиваются под интент;
- текст объясняет именно этот сценарий, а не займы вообще;
- FAQ отвечает на вопросы по интенту;
- перелинковка ведет в близкие интенты и города.

Пример для `/zaimy/na-kartu/`:

- важны способ получения, скорость, поддерживаемые карты, момент зачисления;
- рядом можно ссылаться на `без процентов`, `с плохой КИ`, `срочные`, `круглосуточно`, города.

Пример для `/zaimy/pod-zalog-pts/`:

- важны предмет залога, документы, оценка авто, можно ли продолжать пользоваться машиной;
- рядом можно ссылаться на `под залог авто`, `под залог недвижимости`, города, калькулятор.

## Гео продукта `/zaimy/{city}/`

Роль: страница всех займов в конкретном городе.

Что должно быть:

- H1: `Займы в Москве`, `Займы в Санкт-Петербурге`;
- офферы, доступные в городе или по всей России;
- быстрые переходы в городские интенты;
- блок компаний, которые работают в городе;
- аккуратный локальный текст без выдуманных фактов;
- FAQ с городским контекстом;
- ссылки на `/zaimy/` и интенты.

Гео не должно быть просто заменой слова в шаблоне. Если локальных данных пока нет, городская страница должна хотя бы честно показывать доступные онлайн-офферы, регион работы и дату обновления.

## Интент + гео `/zaimy/{intent}/{city}/`

Роль: точная витрина под сценарий и город.

Примеры:

- `/zaimy/na-kartu/moskva/`;
- `/zaimy/bez-procentov/kazan/`;
- `/zaimy/pod-zalog-pts/novosibirsk/`.

Что должно быть:

- офферы с пересечением `intent + city`;
- короткий уникальный первый экран;
- фильтры, важные именно для интента;
- ссылки на родителя-интент и родителя-город;
- FAQ по сочетанию интента и города;
- блок близких страниц: другие интенты в городе и этот интент в других городах.

Когда такая страница нужна:

- есть спрос или конкурентные аналоги;
- есть достаточный набор офферов;
- сочетание дает полезный выбор;
- можно сделать страницу отличимой от `/zaimy/{intent}/` и `/zaimy/{city}/`.

Когда не нужна:

- офферов нет;
- отличие только в названии города;
- страница получится пустой или почти дублем.

## Карточка компании `/companies/{slug}/`

Роль: доверие и подробности по МФО.

Что должно быть:

- название компании;
- юридическое лицо;
- номер в реестре или лицензии, если применимо;
- условия займов: сумма, срок, ставка, ПСК, способы получения;
- комиссии, подписки, страховки, штрафы;
- регионы работы;
- способы оплаты и погашения;
- отзывы и рейтинг;
- связанные лендинги, где компания участвует;
- дата обновления данных.

Карточка компании должна усиливать коммерческие страницы: с витрины человек переходит в компанию, а из компании возвращается в подходящие подборки.

## Блог и справка `/blog/{slug}/`

Роль: поддерживать коммерческие страницы и закрывать информационные вопросы.

Темы для старта:

- как выбрать займ;
- что такое ПСК;
- чем займ под ПТС отличается от займа под залог авто;
- как читать условия МФО;
- что проверить перед оформлением;
- новости по займам и рынку МФО.

Блог не должен заменять коммерческую страницу. Его задача - объяснять, усиливать доверие и давать внутренние ссылки на нужные витрины.

## Калькуляторы и сервисы `/calculators/{slug}/`

Роль: добавить практическую пользу.

Первые идеи:

- калькулятор переплаты по займу;
- расчет платежа по сроку и сумме;
- сравнение стоимости займа с учетом комиссии/подписки;
- подбор займа по сумме, сроку и способу получения.

Калькулятор должен быть связан с коммерческими лендингами: результат расчета ведет к подходящим офферам.

## Правила генерации страниц

Страницы не должны генерироваться вслепую по всей матрице.

Сначала выбираем:

```text
продукт + список интентов + список городов
```

Потом считаем потенциальный объем:

```text
1 продуктовая + I интентных + C гео продукта + I x C гео-интентных
```

Но публикуем только те страницы, где есть:

- офферы;
- понятный интент;
- уникальная польза;
- нормальная перелинковка;
- возможность поддерживать данные в актуальном состоянии.

## Как использовать документ дальше

1. Выбрать MVP-интенты из `data/competitor-loan-slugs.csv`.
2. Выбрать первые города.
3. Привязать семантику из `data/keywords.csv` к выбранным слагам.
4. Собрать первый реестр страниц MVP.
5. Для каждого типа страницы сделать структуру контента.
6. После этого писать тексты, FAQ и правила перелинковки.

## Короткий промт для лендингов

Нужно спроектировать содержание лендингов для финансового продукта `займы`.

Структура страниц:

- `/zaimy/` - продуктовый хаб;
- `/zaimy/{intent}/` - интентный лендинг;
- `/zaimy/{city}/` - гео продукта;
- `/zaimy/{intent}/{city}/` - интент в городе;
- `/companies/{slug}/` - карточка компании;
- `/blog/{slug}/` - справка и блог;
- `/calculators/{slug}/` - калькуляторы.

Главная идея: каждый слаг - это отдельная витрина под понятный сценарий выбора. Страницы нельзя генерировать только ради синонимов: нужен отдельный интент, подходящие офферы, польза, контент и перелинковка.
